# M11 编排层（0.9.0）实施报告

- 计划：`子计划书-子智能体编排.md` v1.0 定稿（2026-11-25，D41–D47）
- 用户拍板：常驻角色 6、子智能体 6、不预设角色清单（由单会话按需创建）

## 为什么改

0.8.x 的单会话工具面是「worker 的超集里砍掉动手工具」，仍有两个结构性问题：

1. `subagent` 工具一次只能派一个，没有并发上限；宿主 `maxActiveSubagents` 默认 8，超出直接抛 `ACTIVATION_LIMIT_REACHED`，插件没有承接。
2. 派出去的子智能体用完即扔，下次同类任务要从头读同一批文件（实测 12 个真实子会话里 `client.js` 被读 11 次、`package.json` 10 次），并留下大量 `ev=26/tools=0` 的回声会话。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `cordis.patch.yml` | dispatcher preset 的 persona 改成调度纪律；删掉 `tool-subagent` 行；`dispatcher-guard` 的 `keep` 放行 `delegate`、`superagent_status` |
| `~/.dsh/profiles/desktop/cordis.patch.yml` | `- id: subagent` 的 `maxActiveSubagents` 4 → **6** |
| `lib/delegate.js`（新） | 全局工具 `delegate`：`{prompt, role?, cwd?, title?}`；无 role → spawn 临时 worker（worker preset）；有 role → 交给角色会话；FIFO 排队（上限 `singleSession.maxSubagents` 默认 6），命中 `ACTIVATION_LIMIT_REACHED` 也转排队 |
| `lib/roles.js`（新） | 常驻角色 = **独立会话**（不占子智能体名额）：`ensure/dispatch/watch/snapshot/remove/dispose`，上限 `singleSession.maxRoles` 默认 6；完工后回投单会话，并按阈值压缩角色会话 |
| `lib/role-notes.js`（新） | 角色笔记：`<workspace>/docs/角色笔记/<role>/日记.md`（一行一条）+ `事实.md`（结论，标有效/已过时）；派活前注入事实全文 + 最近 5 条日记 |
| `lib/executor.js` | `startActivationQueued()`：worker 撞名额上限时每 3 s 重试到 `max(60s, workerTimeoutMs)` |
| `lib/single-session.js` | 导出 `compactSession(sessionId,{reason,force})` 给角色会话复用压缩，低于 `pressureRatio` 不压 |
| `lib/panel.js` / `client.js` | `/status` 增 `roles`/`delegate`；`/action` 增 `remove-role`；控制台新增「角色」页签（上限/排队/角色表/解除） |
| `lib/config.js` | `singleSession.maxSubagents`、`maxRoles` |

## 0.9.1 修复（2026-11-25 真机首验）

重启后 `/status` 正常，但两处真机问题：

1. **读不到事件的子会话被当成噪音归档**：`sessionController.events` 对没恢复/已入档的子会话返回空，`classifyChild` 把空记录判成 `empty`，维护器直接 `archiveSession`。实测重启后一轮把 12 个（含真任务，tools 26–74）旧子会话按 `noise:empty` 归档。
   修：空记录 → `{unknown:true, reason:'no-events'}`，维护器遇到 `unknown` **不建单、不归档**，只记一次 `singleSessionChildUnknown`。以后只有看得到事件、且确实判定为回声/太薄的才归档。
2. **`/status.delegate` 是 null**：`registerPanel` 传的是 `() => delegate`，而 delegate 是惰性创建。改为 `() => delegateOf()` / `() => rolesOf()`，面板一问就建实例（工具仍只在被调用时才干活）。

单测 174 → **175**（新增「读不到事件不许归档」；归档失败用例补真实回声事件）。
