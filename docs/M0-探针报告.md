## 2 环境与做法

- 宿主：DSH **0.2.2-rc.5**（Desktop 安装版，`app.asar`）。
- 测试 profile：`probe-m0`（从 shipped `web` 模板新建），用户层把默认模型改成 `deepseek-account / deepseek-flash`（桌面登录态可跨 profile 使用；`deepseek-official` 路线在本机没有 API key，首轮曾以 `MISSING_CREDENTIAL` 失败，证据已保留在过程记录里）。
- 探针 bundle：`probe/`（`dsh-superagent-yh-probe`，装进 `probe-m0`，**不属于交付物**）。
- 启动：`dsh probe-m0 --no-open --port 59601`（后台进程），探头在插件 apply 后 2s 自动跑，分两次进程完成 phase 1 / phase 2。

## 3 对实现的关键约束（写代码必须遵守）

1. **必须传 AbortSignal**：`prompt` / `wait` / `state` / `events` 的第二个参数是必填 `signal`；漏传会 `throwIfAborted` 崩溃（首轮实测）。
2. **`cwd` 可以直接传给 `create`**，不必先 `workspaceRegistry.create()`；但官方原型用 workspace 记录目录，面板要列目录时再决定。
3. **会话模型**：`create` 不指定 model，走 profile 默认（`agent-default-model`）；需要角色模型时用 `sessionController.selectModel({sessionId,...})` 或官方原型的 `initializeRoleModel` 思路。
4. **关闭语义**：`sessionController` 没有 dispose；能用的关闭动作是 `cancel`（停当前轮）与 `workspaceRegistry.archiveSession`（从列表归档）。如果自行用 `agents.create()` 建 Agent，才拿得到 `AgentHandle.dispose()`。
5. **重启恢复**：会话日志持久化在 `~/.dsh/sessions/<workspace>/<sessionId>/`，新进程 `resolveAgent` + `prompt` 即可续跑，无需重建会话。
6. **权限**：探针会话默认 `workspace-write` + `approval: ask`；worker 要跑 git/写操作时，按官方原型在 `agent.session` 上 `permissionPresets.set(session,'danger-full-access')`（M1 验证）。
