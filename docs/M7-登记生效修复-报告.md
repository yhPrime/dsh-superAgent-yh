# M7 报告 · 单会话「登记了但不生效」修复（0.7.2）

- 日期：2026-11-24
- 状态：已实施，待真实宿主重启验证
- 关联：`子计划书-单会话与UI.md` v2.8 / D27（本修复是该方向的前提修复，不改设计）

## 1 用户症状

「她还在调用工具自己干活」——点亮图标登记成功，但单会话没有变成调度者，仍像普通会话自己动手。

## 2 根因（两条，都在 `~/.dsh/state/dsh-superagent-yh/logs/single-session.log` 里）

1. **preset 组合非法**，`agentPresets.select` 必然失败：
   - `tool-subagent (@deepseek-ai/dsh-tool-subagent): invalid config: - $.provider missing required value`
   - `tool-subagent-fork ...: $.provider missing required value`
   - `tool-fs-search (...): invalid config: - $.sampleOverCapGlobResults missing required value`
2. **登记时机太晚**：宿主合同是「Select a preset before a session starts its first turn」，已说过话的会话 `select` 只会报 `This session has already started`。旧代码把这个错误扔进日志继续保存登记，用户看到的是「登记成功、行为没变」。

配置对照（`.dsh/profiles/desktop/node_modules/dsh-ops/presets/ops-ptc.patch.yml`）：`tool-subagent` 需要 `provider: spawn` + `toolName: subagent`，`tool-subagent-fork` 需要 `provider: fork` + `toolName: subagent_fork`，`tool-fs-search` 需要显式 `sampleOverCapGlobResults: false`。

## 3 修复

| 文件 | 改动 |
|---|---|
| `cordis.patch.yml` | 两个 preset 的 `tool-subagent` 补 `provider: spawn`，`tool-subagent-fork` 补 `provider: fork`；orchestrator 的 `tool-fs-search` 补 `sampleOverCapGlobResults: false` |
| `lib/single-session.js` | 新增 `isBlank` dep（`agents.turnBoundaryOf(agent.session).lastTurn === 0`）；`register` 先解析 agent：无 → `no-agent`，非空 → `started`（提示新建空白会话、先点亮再发消息）；`selectPreset` 失败 → 撤销登记 + unpin + `preset-failed`；`unregister` 还原与 `maintain` 补切都只在空会话上做，后者每个会话只警告一次 |
| `lib/panel.js` | `/action` 错误码映射：`started`/`no-agent` → 409，`preset-failed` → 500；错误文案透传到客户端 alert |
| `test/unit/single-session.test.js` | harness 增 `blank` / `selectError`；新增「已开始拒绝登记」「preset 失败回滚」两条 |
