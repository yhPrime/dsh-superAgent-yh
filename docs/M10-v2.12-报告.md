# M10 报告 · v2.12 直派子智能体纳管为工单（0.8.2）

> 计划：`子计划书-单会话与UI.md` v2.12（D40）｜日期：2026-11-25｜版本：0.8.2

## 为什么改

- 实测：已登记单会话 `session-fb2c5059-…` 下挂了 **26 个**子会话（13 个「只回复 ok」的测试回声 + 13 个真实任务），没有任何清理。
- 根因：单会话（dispatcher preset）用 `subagent` 工具**直派**的子会话不经过插件工单管线，`state.tickets` 里没有记录；宿主 subagent 运行时也不归档子会话（`archiveSession` 只在 workspace-controller/客户端路径出现），插件的 teardown 只覆盖源触发的工单。
- 用户拍板（A）：把这些子智能体**纳管成工单**，但前提是「她们真的是工单」；噪音不建工单，用完了就归档。

## 改了什么

| 文件 | 改动 |
|---|---|
| `lib/child-tickets.js`（新） | 判定 + 工单文档：`classifyChild`/`firstTaskPrompt`/`childTicketDoc`/`childTicketId`；`source=subagent`、`kind=task`、`id=subagent:<子会话id>` |
| `lib/single-session.js` | `reconcileChildren(view)` 每轮对账；`archiveChild(id)` 走 `archiveSession(id,{stopActivity:true})`，失败 3 次/10 分钟退避并写 `lastError`；噪音判定缓存 `singleSessionChildNoise` |
| `lib/config.js` | `singleSession.adoptChildren`（默认 true）、`singleSession.childIdleMinutes`（默认 2）；normalize/validate |
| `lib/index.js` | 把 `relay` 传进维护器 `deps`，纳管工单能发「开工/完成」 |
| 计划 / 项目信息 | v2.12（D40、M7、E12.22–23）；版本 0.8.2 |

判定只认确定性信号：

1. 子会话事件里出现任意 `tool/call` → 真工单（正在干活）。
2. 否则首条任务 prompt（剥掉宿主追加的 `Your final answer…` 尾段、跳过 `<…>`/`MNEMON`/`Time sampled` 元信息）≥40 字符且（label 非占位 或 ≥80 字符）→ 真工单。
3. 「只回复 ok」这类回声、prompt 太薄、空 → 噪音，不建工单；空闲即归档。

生命周期：新子会话 → 真工单登记（running）并 relay `started`；跑完 → `markDone` + relay `done`；非 running 且空闲 ≥ `childIdleMinutes` → 归档并记 `archivedAt`。已被插件工单管线占用（`childSessionId` 在别的工单里）的子会话不重复纳管。

## 风险与限制

- 只纳管**直接子会话**（`parentSessionId === 单会话`）；子智能体再派生的孙会话暂不纳管。
- 归档走 `stopActivity:true`，宿主若拒绝会退避重试并留 `lastError`，不会阻塞其它维护/压缩。
- 一次维护最多处理全部子会话（无分页），子会话极多时单轮耗时增加；目前量级（几十）无问题。
