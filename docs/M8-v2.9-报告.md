# M8 / v2.9 报告：单会话极简 + worker 显式 preset + 路由走 ctx.llm

- 日期：2026-11-25
- 版本：0.7.3
- 计划：`子计划书-单会话与UI.md` v2.9（定稿，D28 选 2）
- 关联问题：用户报「登记了单会话，她还在调用工具自己干活」（m01924）

## 1. 为什么改

0.7.0 给单会话切了自建调度者 preset（worker 超集），但有两层问题：

1. 那个 preset 组合本身非法（`tool-subagent` 缺 `provider`、`tool-fs-search` 缺 `sampleOverCapGlobResults`），`agentPresets.select` 必然失败，错误只在 `single-session.log`（0.7.2 已修配置 + 只许空白会话登记）。
2. 即便切上了，单会话仍然背着一整套 fs/bash/subagent 工具与长 persona，每轮都在给调度器付上下文钱，且它「有能力」自己动手，行为上就还会自己干。

用户拍板 D28 选项 2：**路由由插件用 `ctx.llm` 一次性判定，单会话只做目的地**，因此单会话本身不需要工具，用宿主内置 `minimal` 即可。

## 2. 改了什么

| 文件 | 改动 |
| --- | --- |
| `lib/host-model.js`（新） | `withTimeout(signal,ms)`；`callHostModel({llm,selection,config,system,prompt,signal,maxTokens})`：按 `config.assessment.provider/model` 或 selection 取路由，缺服务/路由显式抛错 |
| `lib/assessment.js` | 改用 `callHostModel`，删除本地重复实现 |
| `lib/orchestrator.js` | 不再向会话投 prompt；`route(ticket)` 一次 `ctx.llm` 调用解析 `accept/attach/stop/ignore`；不可解析/抛错/无 llm → 回退 rules + `lastError` |
| `lib/config.js` | `singleSession.preset` 默认 `minimal`，校验 `/^[A-Za-z][A-Za-z0-9._-]*$/`；删 `orchestratorPreset` |
| `lib/single-session.js` | 登记/维护按 `singleSession.preset` 切换与回滚（预设不存在→400/500 可见） |
| `lib/executor.js` | `startActivation({ ..., agentPreset: config.workerPreset })`，worker 不继承父 preset |
| `lib/relay.js` | `deliverTo(ticket)`：优先 `ticket.targetSessionId`（校验可用），否则回退 `mainSessionId`；团队模式不再静默 |
| `lib/panel.js` | settings 白名单加 `singleSession.preset` |
| `client.js` | 设置页「单会话 preset」输入（默认 minimal）+ 文案 |
| `cordis.patch.yml` | 删除 `dsh-superagent-yh-orchestrator-preset` 整块（现 96 行，只留 worker preset） |
