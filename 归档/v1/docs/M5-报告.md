# M5 报告（面板）

> 状态：已完成（2026-11-23）｜依据：《计划书.md》§5 M5｜证据：`归档/过程/M5/`

## 1 结果（E6）

一个只读列表 + 设置表单，独立页面，不嵌 iframe、不依赖前端构建：

| 路由 | 用途 | 实测 |
|---|---|---|
| `GET /dsh-superagent-yh` | HTML 面板：总览三态计数、按源分组工单表、最后错误、设置表单 | 200，3404 字节，表格正确列出 2 个 queued 工单 |
| `GET /dsh-superagent-yh/status` | JSON 状态（给脚本/排查用） | 200，`stats`/`sources`/`tickets` 齐全 |
| `POST /dsh-superagent-yh/settings` | 设置 dryRun / mainSessionId / pollIntervalMs | 200；写进 profile 用户层；插件热重载后 `pollIntervalMs` 从 3000 变 7000 |

## 2 安全

- `POST` 校验 `Origin` 必须等于 `webServer.getOrigin()`；无 Origin 返回 **403**（已实测）。
- 请求体上限 8KB；只接受三个白名单字段，其余忽略。
- 设置通过宿主 `configEditor.edit()` 写回用户配置层，不手改 `cordis.patch.yml`。

## 3 踩坑与修复

1. 第一次保存落到了 **探针插件行**（`dsh-superagent-yh-probe`）：因为 `configEditor.entries()` 的 id 带 `include:` 前缀，且我用 `includes('superagent-yh')` 兜底，误配了名字相近的行。修复：先去掉 `include:` 前缀再精确匹配，找不到就报 404 并列出可用 entries，不再猜。
2. 插件代码改动不会 HMR 到已运行的进程（HMR root 为空），面板调试每次都需重启测试实例。

## 4 限制

- 面板是独立页，不是 DSH Web UI 内嵌槽位；后续若要在应用内展示，按 `dsh-doc` 的 Client slot 方式另做（计划书没要求，本期不做）。
- 设置表单只覆盖 3 个常用项；源配置仍用 `cordis.patch.yml`。
