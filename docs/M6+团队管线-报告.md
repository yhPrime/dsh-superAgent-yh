## 1 交付

| 项 | 实现 |
|---|---|
| resolveTarget | `lib/target.js`：工单线索 → QQ 研判 workspace → 默认工作区；只认候选清单；工作区→`intake-*` 单会话（缺则按 autoCreate 建） |
| 统一三层管线 | `lib/executor.js`：assessment → resolveTarget → orchestrator.route → spawnWorker → teardown → parseReport |
| 子智能体驻留 | `subagents.startActivation({provider:'spawn', parent:目标单会话})` + 独立 worktree；终态 `dispose()` + `archiveSession()` |
| 回退路径 | `singleSession.enabled=false` 时走顶层 `worker-<id>`（D19 开关） |
| 监管者 | `lib/assessment.js`：QQ 走 `ctx.llm` 严格 JSON（含 workspace 选择、候选清单校验、超时、失败回退 accept）；GitHub/飞书零调用 |
| 调度者 | `lib/orchestrator.js`：目标单会话 agent 判定 accept/attach/stop/ignore；超时/格式错回退 rules |
| 第三层 | worker preset 加回 `subagent` / `subagent_fork` 工具 |
| 面板 | `/status?sessionId=` 过滤；工单暴露 `mode/workspace/targetSessionId/childSessionId`；会话内 `SuperagentBoard` 挂在 `conversation.session.header.actions.subagent.footer` |
| 回写 | QQ 默认 `confirmWrites=true`（D24）；完成/需要人/失败各一条 |

### 2.3 真实使用模拟

`pipeline-e2e.test.js` 用**真实** store / ticket 状态机 / assessment / orchestrator / target，配假子智能体跑完整链路：

`queued → 研判 → 定位（工作区+单会话）→ 路由 → 子智能体 → 回报 JSON → done → relay(started,done) → 回写来源 → 落盘`

断言：`mode=team`、`workspace`、`targetSessionId`、`childSessionId`、`report.summary`、`dispose=1`、`archive=1`、重开 store 仍为 done。

### 2.4 健壮性

- 研判超时/报错/不可解析 → 回退 accept 且不丢活（单测）
- 研判给出清单外 workspace → 丢弃并计数（单测）
- 目标工作区缺失 / 建会话失败 → 工单 failed 且原因可见（单测）
- 子智能体 `dispose` 抛错 → 仍执行归档、工单终态不丢（e2e）
- orchestrator prompt 抛错 → 回退 rules 并记 `lastError`（单测）
- 回退 worker 路径无 `ticket_report` → failed 且写明「未调用 ticket_report」（单测）

## 4 真实跑通中修掉的问题

1. `workspaceRegistry` / `llm` 在根 ctx 不可直接读 → 改子注入域捕获（真实跑首轮报 `without inject`）
2. `sessionController.archiveSession` 不存在 → 改用 `workspaceRegistry.archiveSession`
3. 仓库未注册成工作区时 `repoPath` 线索无处落 → 路径形态 hint 直接采用（合成 workspace）
4. 换 stateDir 重跑时旧 worktree 占用同名分支 → add 失败自动清理陈旧 worktree 后重试
5. 子智能体名字在父会话 catalog 里必须唯一 → 名字带 attempt/时间后缀
