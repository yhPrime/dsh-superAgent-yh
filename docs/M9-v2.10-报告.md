# M9 / v2.10 纯调度 preset 报告（0.8.0）

日期：2026-11-25｜计划：`子计划书-单会话与UI.md` v2.10（定稿）｜决策：D30（用户选 A）

## 1. 为什么改

0.7.4 真机复查（`session-5ada86f6-e0fc-40b7-b27c-834cf6edaa81`，用户只说了「你好」）：

- `agent-preset/selected` 只有一条 = `minimal`，**D29 的漂移纠回生效**；
- 但凭据里 8 次工具调用：`exp_recall` ×1 + `ops_bash` ×7（读作业规程、`ls`、`npx cc-safety-net ...`），她仍然自己动手。

两条原因：

1. 宿主 `minimal` 在 Windows 上仍挂 `terminal-pwsh` / `persistent-pwsh`（`persistent-shell` 组按平台启用的正是 pwsh）；
2. `ops_bash`（ops 插件）、`exp_recall`（经验库插件）是 **profile 级全局工具**，preset 只决定 preset 自己挂哪些插件，管不到这些全局注册。

结论：靠宿主内置 preset 收敛不了工具面，必须自建「纯调度」preset 并用 `tools.restrict` 在会话 scope 里隐藏全局工具。

契约依据（`cordis_inspect_query` + 宿主源码）：

- `tools.restrict({ allow?, deny? }): () => void` **必须在 scoped ctx（agent.ctx）调用**；名字必须是全局工具，未知名字抛 `names unknown global tool ...`；`run_code` 是保留名（出现即抛）；只限制继承来的全局/祖先工具，restriction 在 scope 链上求交。
- `tool-subagent`：`agentPreset` 必须包含在 `allowedAgentPresets` 里；provider 必须支持 `capabilities.agentPreset` 且不继承父上下文（spawn 可以，fork 不行）。子智能体由 `applyChildComposition` 单独 mount preset 并用自己的 `tools.restrict`，父的限制**不遗传**（E12.21 真机再确认）。

## 5. 风险与未验

- 若 `definitions()` 在 preset mount 时拿不到全局工具（时序），deny 为空 → 收敛失效；日志会打 `dispatcher: no global tool to hide`，真机首查这行。
- 补充（v2.11）：`dispatcher:` 日志走 `ctx.logger`，**不在** `single-session.log`；验收看插件日志（`logs/dispatcher.log`）与会话 `header.tools`，别在 `single-session.log` 里找收敛结果。
- 若 `restrict` 拒绝个别名字（不同 profile 的全局工具集不同），逐个重试后仍未隐藏的会列在 `dispatcher: could not hide ...`。
- 子智能体是否真的不受父 restriction 影响，只有真机能证（`applyChildComposition` 用自己的 `tools.restrict`，理论上独立）。
- 尚未在真实源（GitHub/飞书/QQ）上跑过；纯调度 preset 只影响「人跟单会话说话」这条路径。
