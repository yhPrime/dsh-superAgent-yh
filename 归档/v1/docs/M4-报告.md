# M4 报告（治理）

> 状态：已完成（2026-11-23）｜依据：《计划书.md》§5 M4｜证据：`归档/过程/M4/`

## 1 结果

| 治理项 | 状态 | 证据 |
|---|---|---|
| dryRun 默认 + 只记录不干活 | 通过（实跑） | `dryrun-state.json`：2 个工单 `queued`、`dryRun:true`、无 workdir、无 relay、无 worker 会话 |
| 作者白名单 | 通过（M1/M2 + 单测） | `lib/source/github.js`、`feishu.js` 的 authors 过滤 |
| 每小时唤醒上限 | 实现 + 单测 | `maxTicketsPerHour`（默认 10）+ `hourlyCount()`；达到上限时不推进水位，恢复后补建 |
| 冷却 | 实现 + 单测 | `cooldownMs`（默认 60s）+ `threadCoolingDown()`；同源同线程冷却期内不重复建单 |
| 幂等 | 通过（M1 实跑） | ticket id 去重 + 水位推进；重启后同一 issue 不重复派工 |
| 错误可见 | 通过（实跑） | 401 场景：`sourceStatus.github.ok=false`、`lastError` 含 401 与响应体摘要；轮询继续，不崩 |
| 重启恢复 | 通过（M1 实跑） | 状态跨进程保留、queued 工单可续跑（M0 已验证会话恢复） |
| `send/ack` 写操作确认 | 通过（单测） | `confirmWrites=false` 时 send 抛错、ack 返回 skipped |

## 2 五个异常用例

| 用例 | 结果 | 说明 |
|---|---|---|
| 401 | 通过（实跑） | 记录错误并继续轮询；无工单产生；水位不推进 |
| 断网（fetch 抛错） | 通过（代码路径同 401） | `request` 抛出、`tick` 捕获并记录 `lastError`；未单独造 DNS 断网实跑 |
| 会话被删 | 未实跑 | `resolveAgent` 会返回 `session/not-found`，当前会走 `create` 重建；删除真实会话需要动 `~/.dsh/sessions`（被安全网拦），留到用户环境验证 |
| 重复事件 | 通过（M1 实跑） | 同 issue 重启后仍不重复建单 |
| 并发 | 通过（设计） | `maxWorkers=1`，`tick` 串行 await；两个工单排队依次执行（M1 两个 issue 即按序跑完） |

## 3 限制

- 每小时上限/冷却只有单测，没有专门实跑（需要造 >10 个工单，成本高）。
- 磁盘只读、超长正文、单源挂起：前两项有代码兜底（写失败抛错、正文截断 20K），留到 M6 健壮性一起记录。
