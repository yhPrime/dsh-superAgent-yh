## 2 已验证的行为细节

- **worktree**：`git -C repo worktree add -B superagent/<id> <workRoot>/<id> HEAD`，worker 只在 worktree 内改动；`hello.txt` 内容确为 `M1-OK`。
- **worker 回报**：`ticket_report` 工具注册在 `agent.ctx.tools`（只对该 worker 可见），执行后立即落 state 并触发 relay；worker 实测调用参数 `{status:'done',summary:'已创建 hello.txt',link:...}`，返回 `{"ok":true}`。
- **需要人**：第二个工单由 worker 调用 `status=waiting`，state 变 `waiting`、`report.question` 保留，主线收到「需要人」消息。
- **主线消息**：`superagent-main-m1` 会话日志里 4 条（issue-1 开工/完成、issue-2 开工/需要人），长短均在限额内。
- **重启去重**：重启宿主后 issue-1 的 `updated_at` 变了，但因 ticket 已存在不再建单；issue-2 正常新建。
- **状态机**：`queued → running → waiting/done`，`attempts` 计数与 `lastError` 可见。

## 3 已知限制 / 待办

1. **真实 GitHub 未验**：缺 token/gh。接法已按 REST API 写好（`apiBase` 可配，token 走配置或 `Authorization`），换真 URL + token 即可，不需要改代码。
2. **评论追问（thread 后续）未做**：当前只轮询 issue 本体，评论触发的二次工单留到 M4 幂等/追问场景。
3. **worker preset 仍是 `standard`**：M2/M6 换成精简 worker preset。
4. **会话关闭**：完成后只释放 `ticket_report` 注册，不 dispose 会话（DSH 没有公开 dispose）；面板可看到 `sessionId`。
5. **主线会话自动应答**：测试主线用的是 `standard` preset，收到 relay 后会自己跑一轮工具；生产上主线应是 router preset（M5/打包时补）。
