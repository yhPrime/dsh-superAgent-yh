## 01 先搞清楚：这个项目是干嘛的

一句话：dsh-superagent-yh 是一个 DSH 插件——你在一条会话里说话，插件把活派给 worker 会话和独立 git worktree，结果用三条短消息回到这条线。

核心链路：外部来源（GitHub / 飞书 / QQ）出现符合条件的动态 → 一个轮询周期内自动建工单（Ticket）→ worker 在隔离 worktree 执行 → `ticket_report` 回写来源、主线只收开工 / 需要人 / 完成三条短消息。默认 `dryRun=true`，只记录不干活。

控制台的角色：这套管线的「驾驶舱」——**看**（三态计数、工单、源健康、单会话状态）、**做**（重试 / 取消 / 立即压缩 / 解除单会话 / 移除角色）、**配**（dryRun / 轮询间隔 / preset / 三源配置）。

控制台有 5 个呈现面，全部从同一个 `client.js` 注册：

| 呈现面 | 说明 |
|---|---|
| 左栏主面板 | 完整控制台（概览 / 工单 / 源 / 设置 / 角色，共 5 页签——角色页签为 0.9.0 上线，页签数待拍板 P-A） |
| 右栏页签 | compact 模式，仅概览 + 工单两页签；依赖 better-sidebar，未装自动跳过 |
| 会话头任务板 | 挂会话区头 footer，显示本会话工单：未终态全部（≤20）+ 终态补足到 20（`client.js:393-397`） |
| 输入区登记按钮 | 24×24 图标，空白会话点亮即登记该工作区的唯一单会话（调度者） |
| 独立只读页 | `/dsh-superagent-yh`（路由全小写），第三套独立 HTML，本次冻结降级 |

## 02 现状诊断：能用，但欠账集中在结构与细节（2026-11-26 复核）

全部界面在 `client.js` 一个 **951 行**单文件里：`Console` 组件自 `client.js:424` 起、到 `L863`，440 行、9 个 `useState`；3 套独立 5 秒轮询、3 处内联样式。页签与任务板的真实视觉从 M5 起从未走过浏览器走查。

- **P1 · 巨石组件**：`Console` 440 行（`client.js:424-863`）、9 个 `useState`，视图/请求/表单/忙碌态全混在一起；无法单测视图，compact 与 full 靠三元分支容易漂移。
- **P2 · 轮询重复**：3 套独立 `setInterval`；主面板+右栏同开即两份 `/status`；无 single-flight、无失败退避、页面隐藏仍轮询；任务板取数 `client.js:393-397` 为「未终态全部（≤20）+ 终态补足 20」，不是固定 8 条。
- **P3 · i18n 缺键（v1.1 核实：已闭合）**：`deleteSingle / deleteSingleConfirm / deleteSingleDone` 已存在——`client.js:43`（zh）、`:85`（en）；`test/unit/client-dict.test.js` 已断言差集为空。v1.0 的 S1 因此撤销（见 §09 占位）。
- **P4 · autoCreate（v1.1 核实：UI 已移除）**：`client.js` 已无该开关；只剩 `lib/config.js:69`、`:171` 默认值与 `lib/panel.js:218` 白名单。S4 中该项降级为「配置键清理说明」，不改行为。
- **P5 · 窄栏溢出**：头部 flex 无 flex-wrap、按钮 nowrap；工单为 6 列表格；右栏 320–380px 会挤压/横向溢出（历史风险，从未走查）。
- **P6 · 样式分散**：3 处 `<style>`（胶囊/任务板/控制台，`client.js:199/288/358`），间距字号无统一层，改一处易漏。
- **P7 · 表单裸奔**：form 无 dirty，改一半关面板静默丢失；保存后光标/滚动重置；左右入口各一份草稿。
- **P8 · 可访问性缺失**：任务板 div+onClick 无键盘/读屏；`window.alert / confirm` 与宿主风格不一致；异步提示无 aria-live。
- **P9 · 独立页漂移**：自称只读却带可写设置表单；文案承诺「每 5 秒自动刷新」但无定时器。
- **P10 · 可测性不足**：只有 89 行注册面 smoke 与 i18n 差集测试；渲染/调度/实际使用零测试；`package.json` 无 `scripts`，**没有 `npm test`**，全量用 `node --test test/unit`。

## 03 什么叫「行业标准的控制台」——八条铁律

先立标准再动手。以下八条是重构的验收基准：做完了但缺任何一条，就不算达标。把每一条都当成可判定的检查项，而不是审美偏好。

1. **单一数据源**：同屏视图共享一份数据与一个定时器；轮询有 single-flight、失败退避、隐藏暂停；禁止各自拉数。
2. **视图与数据解耦**：视图是显式 props 的纯组件，数据获取集中在数据层；可独立单测，改一处不读整段。
3. **状态完备**：每个数据区域 loading / empty / error 三态；错误可恢复（有重试入口），不白屏、不静默。
4. **反馈即时且诚实**：异步操作有进行中/成功/失败反馈；文案不承诺做不到的事；危险操作有确认；失败时按钮不卡「保存中」。
5. **信息架构清晰**：总览 → 明细 → 操作三层；一屏一个主任务；页签职责不重叠；窄栏有明确降级而不是溢出。
6. **视觉一致性**：颜色/字号/间距走统一 token；状态色语义固定（成功绿 / 警告琥珀 / 错误红）；同类组件同尺寸同措辞。
7. **可访问性基线**：控件可 Tab+Enter 触发；异步提示 aria-live；不用 alert/confirm；文案 zh/en 成对且不出现原始 key。
8. **可测试可回滚**：调度/过滤/文案可自动验证；注册面有 smoke；每步独立 commit——回滚即 revert + 重启。

## 04 信息架构：页签职责边界与窄栏降级

> **【待拍板 P-A】** 五页签现状 vs D2 四页签：① 保留五页签并更新 D2 ② 按 D2 删「角色」③ 角色移独立页。
> 现状（0.9.0 编排层）：D2 拍板「保持四页签」时画布是 2026-11-25 10:58；「角色」页签是 0.9.0 编排层 23:49 才加的（`client.js:11`、`:17-21` 文案、`:720 rolesView()`、`:847` 分派）。照 D2 原文做等于删掉已上线页签。
> **临时口径（等拍板）：按①保留五页签。**

每个页签回答一个明确的问题，职责不重叠：

- **概览** — 回答「现在整体怎么样」。统计卡（点击切到工单并过滤）、工作空间卡（上下文压力条 / 上次压缩 / 立即压缩 / 打开会话 / 解除单会话）、源健康、最近活动。只放状态与入口，不放配置。
- **工单** — 回答「出了什么事」。状态 chips、搜索、表格、行内日志展开。每行操作不超过 3 个，次要操作收进「更多」；数字用等宽字体。
- **源** — 回答「接上了没有」。GitHub / 飞书 / QQ 每源一张卡：健康状态 + 触发条件摘要。只读展示，编辑一律去设置页，不在两处都能改。
- **设置** — 回答「要改什么」。分组表单（基础 / 单会话 / 三个源）+ 底部 sticky 保存条。废弃项不再以可用开关出现；token 只显示掩码。
- **角色**（P-A 临时保留）— 回答「有哪些常驻角色在跑」。角色列表 + 移除操作（`/action remove-role`）；不在此页编辑角色笔记。

**窄栏降级（右栏 320–380px，验收三档：320 / 360 / 380）**
- 头部允许换行，次要按钮收进「更多」，标题 / 版本 / 胶囊开关 / 关闭不被挤断
- 工单表格隐藏「尝试 / 最后错误」列，错误放标题下第二行；禁止横向滚动
- 页签保持可点，间距收紧但不重叠
- 验收线：三档下 `scrollWidth <= clientWidth`，且任意两个可交互元素矩形不相交（人工截图判定）

**导航原则**：总览卡可点击跳明细；每个操作有明确的下一跳（做完去哪、看结果去哪）；关闭永远在右上角；当前页签视觉高亮唯一。

## 05 设计令牌：先定语义，再写样式

铁律：全部沿用宿主已有的 `--dsw-alias-*` CSS 变量，不新增颜色体系、不引入 CSS 框架；样式必须引用语义而不是写死值。

**颜色语义** — 状态色只表语义不做装饰：进行中=蓝/紫、成功=绿（#10B981）、警告=琥珀（#F59E0B）、错误=红（#EF4444）、禁用=灰。同一语义全控制台只有一个值；状态徽章 = 圆点 + 文字，不用彩虹标签。强调色（#A259FF）只用于主操作与选中态，不做装饰。

**字号阶梯（5 级封顶）** — 页标题 34 / 区块标题 16–20 / 正文 14–15 / 辅助 12–13 / 数字与代码等宽 11–13。正文行高 ≤1.6；同级标题全控制台同字号，不允许「差不多大」。

**间距** — 4px 基数网格：卡片内边距 16、卡片间距 16、区块间距 24–32、页面留白 56–64。所有间距是 4 的倍数，禁止随手写 13、22 这种值。

**卡片** — 圆角 10–12、白底或 #FAFAFB、静息阴影 `0 1px 2px rgba(0,0,0,.04)`、描边 #E5E5E5；交互态阴影带强调色 tint。表格行高 ≥40，按钮圆角 8。

**组件规则** — 主按钮每屏最多 1 个且强调色；统计卡点击 = 过滤入口（可点击的卡片要有 hover 态与 cursor）；表单标签放字段上方；开关/输入框尺寸全控制台统一；3 处内联 CSS（`client.js:199 / 288 / 358`）合并为一份模块级常量，类名不变；视觉是否走样按 §09 S3 的截图判据判定，不写「零变化」。

## 06 数据层：一处数据源、一份轮询

目标 G1。做法：在 `client.js` 模块内建一个极小的 consoleStore（80–120 行，是函数边界不是框架），替换现有 3 套独立轮询。

```
宿主 state.json → panel 路由（契约不变）→ consoleStore（新增）→ 主面板 / 右栏 / 任务板 / 登记按钮
```

**consoleStore 规格（每条都要有单测）**
- 资源三种：`status`（全量 `/status`，主面板/右栏共用）、`status:<sessionId>`（任务板，保留 `?sessionId=`）、`single:<sessionId>`（登记按钮）
- `subscribe(resource, listener)`：首个订阅启动一个 5s 定时器，最后一个退订停表；document 不可用（单测环境）时不启动
- single-flight：同资源有在途请求时复用，不叠发
- 失败退避：5s → 10s → 20s → 30s 封顶，成功复位
- `document.hidden` 时暂停，恢复可见立即补拉一次
- `refresh(resource)`：操作后显式刷新，替代各组件各自的 reload

**100 条上限语义（v1.1 新增）**：全局 `/status` 在 `lib/panel.js:303` 先过滤、`:329` `tickets.slice(-100)`。任务板若改订阅共享 `status`，就变成「服务端先切最近 100、客户端再按会话过滤」——工单总数 >100 时，本会话的旧工单会被切掉；现有 `?sessionId=` 路径（先按会话过滤再切 100）没有此问题。**因此任务板保留 `?sessionId=`，作为 `status:<sessionId>` 独立资源接入 consoleStore**；若将来要并入全局 `status`，必须先拍板接受「只显示全局最近 100 中本会话单据」这一语义并写进发布说明。

**消费者改造**：主面板与右栏的 Console 订阅 `status`；任务板订阅 `status:<sessionId>` 并本地复刻 `filterTicketsForSession`（6 行，与 `lib/panel.js` 导出函数在同一 fixture 矩阵上逐例相等）；登记按钮订阅 `single:<sessionId>`，登记成功后 refresh 该资源。

**验收口径**：自动——假定时器覆盖订阅启停 / single-flight / 退避 / hidden / refresh 合并；过滤 parity 逐例相等。人工——重启后同开主面板+右栏，30 秒固定窗口内 `/status` 请求数 **≥6 且 ≤8**；>8 判失败，<6 先查定时器是否停摆；Network 截图留证。

## 07 交互与可访问性：键盘能到、反馈可见、文案诚实

**键盘与读屏（G6）**：交互控件可 Tab 到、Enter/Space 触发；任务板行从 div+onClick 改 button（或 role=button + tabIndex=0 + 键盘处理）；msg/error 容器加 `aria-live=polite`；控件带 aria-label / aria-pressed / title。

**阻断式弹窗全部替换**：`window.alert / window.confirm` 移除——登记失败改输入区旁 role=alert 行内提示；压缩/删除单会话用面板内确认；文案写清后果（如「先注销登记、再归档该会话」）。

**表单保护（G5）**：form 加 dirty 标记；切页签/关闭时提示「有未保存修改」（D4 方案 a，不引入 localStorage 草稿）；保存中禁用 + loading，失败恢复可点并显示错误位置；保存成功不重建整个表单。

**文案规范（G4）**：zh/en 键集合差集为空——代码使用的键必须是 DICT 键的子集，由 `test/unit/client-dict.test.js` 守护；新增键成对；不出现原始 key；文案不承诺不存在的行为（反面教材：独立页的假「每 5 秒自动刷新」）。

**废弃处理（v1.1 修正）**：autoCreate 已从设置页移除（D5 方案 a，`client.js` 无命中）。本节只留「配置键清理说明」：`lib/config.js:69`、`:171` 的默认值与 `lib/panel.js:218` 白名单保留并标 deprecated，不删键、不迁移——已装 profile 不因读不到键而报错。原则：UI 与定稿决策永远一致，废了就不显示，而不是「显示但别点」。

**空态与错误态（铁律 3）**：每个数据区域三态齐备——loading 有占位、empty 有引导（如「暂无工单——等一个来源触发或去源页检查配置」）、error 有重试入口。host 500 / 超时 / 返回非 JSON 时控制台显示错误卡，不白屏、不静默、不产生未捕获 Promise。

- G6 全控件键盘可达；`client.js` 中 `window.alert|window.confirm` 命中数为 0。

**四测（按工作台宪法 §13.3：迭代到无新缺陷，至少两轮 + 修复回环）：**
